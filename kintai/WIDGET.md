# 既存アプリに打刻ボタンを組み込む（B案）

`index_b.html`（石材業務管理アプリ）の画面内で、そのまま出勤・退勤できるようにします。
勤怠アプリへ移動する必要がなくなります。

**作業は `index_b.html` に3か所足すだけです。** 既存のコードは1行も変更しません。

---

## 0. 前提の確認（すでに満たしています）

| 条件 | 状況 |
|------|------|
| 権限 | `index_b.html` の `SCOPES` に `Sites.ReadWrite.All` がある（5971行目）。**追加不要** |
| ログイン | `index_b.html` の `getToken()`（22095行目）をそのまま使う。**再ログイン不要** |
| Azure 設定 | 同じアプリ登録・同じ戻り先アドレス。**変更不要** |
| 位置情報の許可 | 同じサイト（`111rbubu-art.github.io`）なので勤怠アプリと共有。**再許可不要** |
| SharePoint | 同じサイト・同じリスト。**変更不要** |

> **重要**：MSAL（ログインの仕組み）は既存アプリのものをそのまま使います。
> ウィジェット側では初期化しません。同じアプリIDで2つ作ると認証が不安定になるためです。

---

## 1. 読み込むファイルを足す

`index_b.html` の **`</body>` の直前**、または既存の `<script>` 群の**いちばん後ろ**に、
次の5行を足します。

```html
<script src="./kintai/config.js"></script>
<script src="./kintai/util.js"></script>
<script src="./kintai/geo.js"></script>
<script src="./kintai/graph.js"></script>
<script src="./kintai/widget.js"></script>
```

### 順番は変えないでください

`config.js` → `util.js` → `geo.js` → `graph.js` → `widget.js` の順に依存しています。

### 名前の衝突は起きません

勤怠側の名前はすべて `kt` / `KT_` / `ktw` で始めてあります。
`index_b.html` にある `getToken` `msalApp` `CLIENT_ID` `TENANT_ID` `SP_HOST`
`KOUJI_LIST_ID` などと重なるものはありません。
`$` という関数も `index_b.html` には存在しないことを確認済みです。

**`auth.js` は読み込まないでください。** MSAL が二重に初期化されます。

---

## 2. 置き場所を作る

打刻ボタンを出したい場所に、空の入れ物を1つ置きます。

```html
<div id="kintai-widget"></div>
```

**おすすめの置き場所**

- トップ画面の上部（毎日いちばん最初に見る場所）
- ヘッダーの下

幅は置いた場所いっぱいに広がります。高さは約90pxです。

---

## 3. 起動する

`</body>` の直前に次を足します。**手順1のスクリプトより後**に置いてください。

```html
<script>
  ktWidgetInit({
    el: '#kintai-widget',
    getToken: getToken        // ← 既存アプリの getToken をそのまま渡す
  });
</script>
```

### ログイン後に起動したい場合

`index_b.html` はログイン完了後に `startApp()` を呼びます。
そこに合わせたい場合は、`ktWidgetInit(...)` を `startApp()` の中の最後に移してください。
呼ぶ場所が変わるだけで、書き方は同じです。

---

## 4. できあがり

```
佐藤 次郎  勤務中  10:07  本社
┌────────────────────────────────────────────┐
│                    退  勤                    │
└────────────────────────────────────────────┘
出勤 10:07  [取消]
```

- **出勤と退勤だけ**の1ボタンです。**いま押せるものだけ**が出ます
  （未出勤なら「出勤」、出勤済なら「退勤」）
- 休憩の打刻はありません。必要なときは勤怠アプリ（`kintai/`）で打てます
  （勤怠アプリ側で休憩を打った場合は、このボタンが「休憩終了」に変わります）
- 打刻すると位置が自動で記録され、判定した現場名が出ます
- 通信できないときは端末に保留し、**次にこの画面を開いたときに自動で送信されます**
- 表示は明るい配色・暗い配色の両方に自動で合わせます

### 押し間違いへの備え

- **出勤から60分以内に退勤を押すと**「出勤からまだ○分です。退勤にしますか？」と確認します
- **押した直後15分間は［取消］が出ます。** 押すと勤怠アプリと同じ取消申請になり、
  管理者が確認するまでその打刻は集計から外れます
- 15分を過ぎた場合や前の日のぶんは、勤怠アプリの
  ［打刻をまちがえたとき・忘れたときは］から申請してください

詳しくは `SETUP.md` の §4-7 をご覧ください。

## 5. 動作確認

組み込んだあと、次を確認してください。

- [ ] 既存アプリの見た目が崩れていない（ウィジェットの CSS は `.ktw-` のみを対象にしています）
- [ ] 既存アプリの機能が今までどおり動く
- [ ] ウィジェットに自分の名前が出る
      - 出ない場合 → 社員マスタの `UserPrincipalName` が合っていません
- [ ] ［出勤］を押すと時刻と現場名が出る
- [ ] 勤怠アプリ側（`kintai/`）の履歴にも同じ打刻が出ている
- [ ] ブラウザの開発者ツール（F12）のコンソールに赤いエラーが出ていない

## 6. 注意点

### PCからの打刻は位置の精度が粗くなります

PCには GPS がないため、Wi-Fi や回線からの推定になります。**数百m〜数km**の誤差が出ます。
事務所の判定半径が150mだと「事業所外」と判定され、要確認の印がつくことがあります。

対策は次のどちらかです。

- 現場マスタで事務所の `RadiusM` を大きくする（例：`2000`）
- PCからの打刻は要確認がつく前提で運用し、管理者が［確認済］を押す

### スマホは勤怠アプリのほうが速いです

`index_b.html` は約21,000行あるため、読み込みに時間がかかります。
現場からスマホで打刻する場合は、**勤怠アプリをホーム画面に置いたほうが速い**です
（A案のリンクもそのために有効です）。

このウィジェットは、**事務所のPCで作業しながら打刻する**用途に向いています。

### 元に戻すには

足した3か所（スクリプト5行・`<div>` 1行・起動の数行）を消すだけです。
既存のコードには触れていないので、それだけで完全に元に戻ります。

