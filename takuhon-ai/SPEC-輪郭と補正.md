# 拓本から輪郭を起こし、フォントで補正する（仕様）

2026-09-11 決定。実装はこれから。

## 何のためか

**次に彫る行の校正を作る**ため。2 つの使い道がある。

1. **行の見立て**（字の高さ・字送り・画線の太さを測る）を、きれいな墨で測り直す
2. **新しい行に、前の行と同じ字があるとき、その字に形を合わせる**

2 がこの仕様の芯。**同じ字が前の行と新しい行で違って見えるのが、いちばんまずい**（並べて見られるので一目で分かる）。
だから**彫ってある字をなぞって、そのまま使う**。

## AI は 2 段に分ける（2026-09-12 決定）

```
① 読む      拓本      → 綺麗な墨       （正解＝人が直した拓本の墨）
② 整える    綺麗な墨  → 書体らしい形   （正解＝フォントそのもの）
```

**②はこちらのデータを 1 組も必要としない。** フォントを劣化させて「にせの入力」を作り、
元のフォントを正解にすれば、**何千組でも自動で作れる**。データが貯まる前に始められる。

分ける利点

1. **②はデータ不要**。今日から学習できる
2. **どちらが悪いか切り分けられる**。「拓本を読めていない（①）」のか
   「整え方が下手（②）」のか、別々に確かめられる。1 つのモデルだと分からない
3. **②が気に入らなければ切れる**。①だけ使って、あとは手で、という逃げ道が常にある

**①の正解は今までどおり（直した拓本の墨）。作業の流れは変わらない。**

### ②の落とし穴 ― 劣化のさせ方を間違えると「変形」になる

**まずい作り方**

```
フォント → ぼかす・角を丸める → にせ入力
正解 = 元のフォント
```

これだと AI は「**どの字か当てて、フォントを描き直す**」ことを覚える。
彫った職人の癖（画の位置・長さのずれ）は**ぜんぶ消される**。
これは**手で変形させるのと同じ**で、**拓本時点の正解ではないので、合っているか判断できない**。

**正しい作り方**

```
フォント
  ↓ まず 形を崩す（画を少しずらす・伸ばす・太さを変える）  ← 「職人の癖」の代わり
崩れた字（＝これが正解。角は立っている）
  ↓ さらに 縁を劣化させる（角を丸める・ぼかす・欠けさせる・かすれさせる）
にせの拓本（＝入力）
```

**正解は「崩れたまま、角が立っている字」。**
こうすると AI が覚えるのは「**与えられた形はそのままに、縁だけ書体らしく整える**」こと。
**位置のずれは保たれ、角だけ立つ。**

**劣化で太さを系統的に変えてはいけない**（変えると「太さを元に戻す」ことを覚えてしまい、
拓本の太さを無視するようになる）。太さの違いは**崩し（正解の側）**でつける。

### ②では手がかり（フォント）を見せない

②の仕事は「**与えられた形の縁を整える**」こと。**どの字かを当てる必要がない。**
それなのにフォントを見せると、「フォントをそのまま描けば正解に近い」という**近道**を
覚えかねない。それは彫った職人の癖を消す動きで、**手で変形させるのと同じ**。

`train.py --nohint`（画面の②はこれを自動で付ける）。
`make_synth.py` は `hint1.png` を作るが、学習では常に白紙に差し替える。

実測（ゴシック体・1850 組・18 回め）：
一致（手がかりあり）90% ／ 一致（手がかり無し）**88%** ——差は 2 ポイントしかなく、
手がかりに頼っていないことが分かる。**見るべきは「手がかり無し」の方**（本番では渡さない）。

### ②は「実際に彫っている書体」で学習させる

楷書体の癖を覚えさせたいのだから、その書体のフォントで劣化データを作る。
書体を変えるなら、その書体でも作り直す。

## 役割を分ける

```
AI（U-Net）がやること   拓本 → 「どこが墨か」の確からしさ（0〜1 の濃淡）
────────────────────────────────────────────────
きまりごとでやること
  1. 確からしさ → 輪郭線（0.5 の等高線をたどる）
  2. 行ぜんたいを測る
  3. フォントと見くらべて、おかしい所だけ直す
```

**AI は「読む」だけ。「直す」のは全部きまりごと。**
理由は**直した理由が見えるから**。AI に直させると、なぜそうなったか誰にも分からなくなる。
きまりごとなら、どこをどれだけ直したかを画面に出せるし、気に入らなければ止められる。

## どこから何を取るか

**フォントは「骨格」として使い、「太さ」は拓本の実測から取る。**
フォントの太さをそのまま当てると、その拓本の彫りの太さから外れる
（フォントの太さは書体の都合で決まっているだけ）。

| 何を | どこから |
|---|---|
| 画がどこにあるか・つながっているか | **フォント** |
| 画の太さ | **拓本の実測**（行の見立てが出す。試しの拓本で 1.37mm） |
| 字の高さ・幅・字送り | **拓本の実測** |
| 縁の形（払い・ハネの表情） | **拓本そのもの** |

## 直す場面は 4 つ

| | やること | フォントの位置を使うか |
|---|---|---|
| **（あ）明らかに細い** | その画を、**その場で**太らせる | **使わない** |
| **（い）途切れている** | 切れ目を、**その画の向きに**つなぐ | つながっているべき画か、の確認だけ |
| **（う）欠けている** | フォントを見て、足りない所を足す | **使う（ここだけ）** |
| **（え）余計なもの** | 小さい塊を捨てる | **使わない** |

### 1 画ずつの癖は、消してはいけない

**職人の癖こそが手本**。前の行と同じ字を合わせるのだから、画の位置が少しずれているなら、
新しい字も同じようにずれていないと揃わない。**補正で癖を消したら、目的を裏切る。**

そのため、**補正は「拓本の画そのものに沿って」だけ行う**。
フォントの位置へ引き寄せる処理は入れない。
（あ）（い）（え）はフォントの位置をまったく使わないので、
**画が 1mm ずれていようが 3mm ずれていようが、ずれたまま太くなり、ずれたままつながる**。

### （う）だけ注意が要る

「欠け」と「大きくずれた画」の見分け。取り違えると、在るのに足して画が二重になる。

1. **探す範囲を広く取る**（字の大きさの 15%。それだけ離れていても「同じ画」とみなす）
2. **1mm² の上限**（下の設定）。大きく足そうとした時点で止まる
3. **迷ったら直さず、人に知らせる**

［② 拓本に大まかに合わせる］で字ぜんたいの位置は合っているので、残るずれは画ごとの癖だけ。

## 守ること

- **黙って直さない。** 直した所を色で見せる（足した所・太らせた所）
- **上限を超えたら直さず、知らせる**
- **1 手で戻せる**

## 設定（決め打ちにしない。画面から変えられるように）

| | 初期値 | 意味 |
|---|---|---|
| 太さの補正 | **0.3 mm** まで | これを超えて太らせない |
| 欠けの補完 | **1 mm²** まで | これを超えて足さない |
| 画を探す範囲 | 字の **15%** | これだけ離れていても同じ画とみなす |

最初は厳しめ（すぐ人に聞く）にしておき、使いながら緩める。

## サーバー側に要る変更

**確からしさ（0〜1）をそのまま返す口**だけ。
いまの `/api/takuhon/clean` は 0.5 で切った白黒しか返さないので、輪郭を追うときに情報を捨てている。
濃淡のまま返せば、**ます目（0.0835mm）より細かい縁**が取れる。

## ［② 拓本に大まかに合わせる］は、この流れでは要らない

2026-09-11 追記。実際の運用はこうなる。

```
新しい行の文字を入力する
  └ その字が拓本の行にもあるか探す
      ├ ある → 拓本のその字に合わせる（＝なぞる）。AI はフォントを手がかりにできる
      └ 無い → フォントから作り、実測した値（高さ・幅・画線の太さ）に合わせる
```

②が出すのは「フォントを拓本に寄せた、**微妙にずれた形**」で、**正解ではない**。
正解は拓本の方。正解でないものを学習の手がかりに入れるのは筋が悪い。

②がいま担っている仕事は 3 つ。それぞれこうする。

| ②の仕事 | どうするか |
|---|---|
| **位置合わせ** | **自動にする**（内部処理へ格下げ）。要る精度は「どの画とどの画が同じか分かる」程度＝**字の 15%**。なぞった外枠と実測した字の高さから計算できる。**人が押す必要はない** |
| **手がかり2 を作る** | **やめる**（下） |
| **学習データの保存の引き金** | **［この字をなぞって手本にする］に移す**。人が「これは良い」と判断した瞬間に貯まるので、質も上がる |

### 手がかりは 1 枚にする

| | 中身 | どうするか |
|---|---|---|
| **ヒント1** | 元のフォントの字形 | **残す**。「いま見ているのはこの字だ」と教える。地のざらつきと画を見分けるのに効く |
| **ヒント2** | 大まかに合わせたあとの字形 | **やめる**。ずれた答えを足すだけで、AI がそれに引っ張られると彫ってある形から離れる |

**学習データが 0 組のうちに決める。** 貯まってから変えると全部取り直しになる。

### 消す順番

なぞりが動くまでは、いまのやり方（フォントを寄せて手で直す）が唯一の道なので、
先に壊してはいけない。

1. **いま** … ヒント2 を渡すのをやめる（データ 0 組のうちに）
2. なぞり＋補正を作る
3. 実際の拓本で「前の行と並べて違和感がない」ことを確かめる
4. **そこで初めて**②のボタンを外す

②はしばらく残すが、**頼らなくなる**。

## 作る順番

1. **輪郭化**（確からしさ → 輪郭線）… **済（彫刻原稿 v20.89／［③ 拓本をなぞる］）**
2. **フォントで補正**（上の 4 場面＋見せ方）… **済（彫刻原稿 v20.90／［フォントで補正する］）**
3. 学習データが貯まったら **AI を差し込む**（`RUB.clean` の差し込み口は作成済み）
4. **帯を通す**（AI は 1 文字ずつしか見ないので、行ぜんたいは少しずつ重ねて通し、つなぎ合わせる）

**1 と 2 は AI が無くても作れる。** いまのしきい値で拾った墨を相手に動かして、
**「AI の墨がどれくらい綺麗なら実用になるか」の物差し**にする。
