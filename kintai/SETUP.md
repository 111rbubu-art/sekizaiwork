# 勤怠管理アプリ 導入手順

このアプリを動かすまでにやることは4つです。上から順に進めてください。

1. 就業規則の改定（システムより先に）
2. SharePoint にリストを6本つくる
3. Azure にアプリの戻り先アドレスを1行足す
4. 社員マスタと現場マスタに実データを入れる

所要時間はおおむね1〜2時間です。

---

## 0. 先に済ませること — 就業規則の改定

位置情報は個人情報保護法上の個人情報です。**説明と同意なしに記録を始めると、
プライバシー侵害として争われるおそれがあります。** 次を先に整えてください。

- [ ] 打刻時に位置情報を取得すること、その目的（勤務地の確認と労働時間の適正な把握）、
      保存期間、閲覧できる範囲を就業規則に記載する
- [ ] 従業員へ事前に説明し、書面で同意を得る
- [ ] 有給休暇を古い付与分から消化する旨を就業規則に記載する
- [ ] 私物スマートフォンを使う場合、通信費の負担を取り決める

アプリ側でも初回起動時に説明画面を出し、同意した日時を記録します（後述）。

## 1. SharePoint にリストをつくる

サイト `https://shojisekizai.sharepoint.com/sites/stoneworks` に、次の6本を
**「空白のリスト」** から作成します。

> **列の名前は必ず半角英数字で作成してください。**
> 日本語で作ると内部名が `_x52dd_...` のような文字列に変換され、アプリから読めなくなります。
> 日本語の見出しが欲しい場合は、列を作ったあとに「列の名前を変更」で日本語に直してください
> （内部名は英数字のまま維持されます）。

> **日付は「1行テキスト」で作成しています。**
> SharePoint の日付型は保存時に時差の影響を受け、1日ずれる事故が起きやすいためです。
> `2026-08-04` の形式で入力してください。

### 1-1. `KintaiEmployees`（社員マスタ）

| 列名 | 型 | 設定 |
|------|----|------|
| `Title` | （既定の列） | 社員番号を入れる。例 `001` |
| `EmpName` | 1行テキスト | 氏名 |
| `UserPrincipalName` | 1行テキスト | **M365 のメールアドレス。これで本人を照合する** |
| `HireDate` | 1行テキスト | 入社日 `YYYY-MM-DD`。**役員は空欄で構いません**（有給の対象外のため） |
| `EmpType` | 選択 | `正社員` / `パート` / `アルバイト` / `役員` |
| `WeeklyDays` | 数値 | 週の所定労働日数。正社員は `5` |
| `WeeklyHours` | 数値 | 週の所定労働時間。例 `40` |
| `WorkStart` | 1行テキスト | 所定始業 例 `08:00` |
| `WorkEnd` | 1行テキスト | 所定終業 例 `17:00` |
| `BreakMin` | 数値 | 所定休憩（分）例 `60` |
| `IsAdmin` | はい/いいえ | 管理タブを使える人。**既定値：いいえ** |
| `Active` | はい/いいえ | 在籍中。**既定値：はい** ← 忘れると一覧に出ません |

### 1-2. `KintaiPunchLogs`（打刻ログ）★中核

| 列名 | 型 | 設定 |
|------|----|------|
| `Title` | （既定の列） | 社員番号 |
| `PunchType` | 選択 | `出勤` `退勤` `休憩開始` `休憩終了` `位置情報同意` `位置情報不同意` |
| `WorkDate` | 1行テキスト | 勤務日 `YYYY-MM-DD` |
| `ClientTime` | 1行テキスト | 端末が送ってきた時刻（照合用） |
| `Lat` | 数値 | 緯度。小数点以下 **6桁** |
| `Lon` | 数値 | 経度。小数点以下 **6桁** |
| `AccuracyM` | 数値 | 測位精度（m） |
| `LocationStatus` | 1行テキスト | 取得成功／拒否／失敗／タイムアウト／同意なし |
| `LocationSource` | 1行テキスト | GPS／ネットワーク |
| `SiteName` | 1行テキスト | 判定した地点名 |
| `SiteDistM` | 数値 | 地点の中心からの距離（m） |
| `UserAgent` | 複数行テキスト | 端末情報 |
| `ManualTime` | 1行テキスト | 過去分を手入力したときの時刻 `YYYY-MM-DDTHH:MM`。空なら実際の打刻 |
| `Reviewed` | はい/いいえ | 管理者が確認済にした印。**既定値：いいえ** |
| `AdminNote` | 1行テキスト | 管理者のメモ |
| `Voided` | はい/いいえ | 取り消した打刻。**既定値：いいえ** |
| `VoidReason` | 1行テキスト | 取り消した理由 |

**打刻時刻と打刻者の列はつくりません。** SharePoint が自動で付ける
「作成日時」と「作成者」を正として使います。この2つは端末から書き換えられないため、
時刻の偽装となりすましを構造的に防げます。

**バージョン履歴を有効にしてください**（リストの設定 → バージョン設定 → 「はい」）。
管理者が修正した場合も履歴が残り、監査に耐えます。

### 1-3. `KintaiSites`（現場マスタ）

| 列名 | 型 | 設定 |
|------|----|------|
| `Title` | （既定の列） | 地点名。例 `本社` `慈宏寺` |
| `SiteType` | 選択 | `事業所` / `現場` / `取引先` |
| `Lat` | 数値 | 緯度。小数6桁 |
| `Lon` | 数値 | 経度。小数6桁 |
| `RadiusM` | 数値 | 判定半径（m）。事業所は `150`、広い霊園は `300`〜`500` |
| `Active` | はい/いいえ | **既定値：はい** |

**緯度経度の調べ方** — Google マップでその場所を右クリックすると、一番上に
`35.703291, 139.622411` のような数字が出ます。左が緯度（`Lat`）、右が経度（`Lon`）です。
クリックするとコピーされます。

### 1-4. `KintaiLeaveGrants`（有給の付与）

**通常は空のままで構いません。** 付与日数はアプリが入社日から自動計算します。
出勤率が8割を切った年や、法定を上回る日数を付与した年だけ行を追加してください。

| 列名 | 型 | 設定 |
|------|----|------|
| `Title` | （既定の列） | 任意。例 `001_2026-10-01` |
| `EmpNo` | 1行テキスト | 社員番号 |
| `GrantDate` | 1行テキスト | 付与日 `YYYY-MM-DD`（自動計算と同じ日付にすること） |
| `GrantDays` | 数値 | 付与日数を手で決める場合 |
| `AttendRate` | 数値 | 出勤率（%）。`80` 未満なら付与なしになる |
| `Note` | 1行テキスト | 備考 |

### 1-5. `KintaiLeaveRequests`（有給・代休の申請）

| 列名 | 型 | 設定 |
|------|----|------|
| `Title` | （既定の列） | アプリが自動で入れる |
| `EmpNo` | 1行テキスト | 社員番号 |
| `LeaveDate` | 1行テキスト | 取得日 `YYYY-MM-DD` |
| `LeaveType` | 選択 | `全日` `午前半休` `午後半休` `時間単位` `代休` |
| `Hours` | 数値 | 時間単位のときの時間数 |
| `Days` | 数値 | 消化日数（アプリが計算して入れる） |
| `Status` | 選択 | `申請中` `承認` `却下` `取消`。**既定値：申請中** |
| `Reason` | 複数行テキスト | 事由（記入は任意。法律上、申告義務はありません） |
| `ApprovedBy` | 1行テキスト | 承認者 |
| `ApprovedDate` | 1行テキスト | 承認日 |

### 1-6. `KintaiHolidays`（休日の例外）

土日・毎月14日15日は `config.js` で自動判定するので、**このリストには例外だけ**を入れます。
年末年始、夏季休暇、祝日、振替出勤日などです。

| 列名 | 型 | 設定 |
|------|----|------|
| `Title` | （既定の列） | 名称。例 `年末年始` |
| `HolidayDate` | 1行テキスト | `YYYY-MM-DD` |
| `HolidayType` | 選択 | `法定休日` / `所定休日` / `平日`（振替出勤日は `平日`） |

## 2. 打刻ログの権限を絞る

打刻ログを「あとから書き換えられない記録」にします。ここが改ざん防止の要です。

### 2-1. 追加専用の権限レベルをつくる

1. サイトの設定 → **サイトの権限** → 詳細設定 → **権限レベル**
2. 「権限レベルの追加」→ 名前を `打刻の追加のみ` にする
3. **チェックを入れる項目**：`アイテムの表示`、`アイテムの追加`、`ページの表示`、
   `アプリケーション ページの使用`、`ユーザー情報の参照`、`リモート インターフェイスの使用`、
   `自己更新の管理`
4. **チェックを外す項目**：`アイテムの編集`、`アイテムの削除`、`バージョンの削除`

### 2-2. リストに割り当てる

1. `KintaiPunchLogs` → リストの設定 → **このリストに対する権限**
2. **「権限の継承を中止」** をクリック
3. 従業員に `打刻の追加のみ` を割り当てる
4. 管理者（社長）に `フル コントロール` を割り当てる

### 2-3. 自分の記録だけ見えるようにする

`KintaiPunchLogs` → リストの設定 → **詳細設定**

| 項目 | 設定 |
|------|------|
| 読み取りアクセス | **ユーザーが作成したアイテムのみ読み取る** |
| 添付ファイル | 無効 |

これで従業員は自分の打刻だけを見られ、他人の記録は見えません。
管理者はフルコントロールなので全員分を見られます。

> `KintaiEmployees` `KintaiSites` `KintaiHolidays` `KintaiLeaveGrants` は
> 従業員に **閲覧のみ**、管理者に **フルコントロール** を割り当ててください。
> `KintaiLeaveRequests` は従業員に **投稿（Contribute）** が必要です（申請と取消のため）。

## 3. Azure に戻り先アドレスを追加する

既存の石材業務管理アプリと同じアプリ登録を使いますが、
勤怠アプリは別フォルダーにあるため、戻り先アドレスの追加が1行必要です。

### 手順

次のリンクを開くと、アプリの登録画面に直接飛べます。

```
https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationMenuBlade/~/Authentication/appId/f6d7ca4a-f786-4a91-bdb0-6d8e576e6aea
```

「sekizaiwork」の概要画面が開いた場合は、右側にある
**「リダイレクト URI : ○ 個の Web、○ 個の SPA、…」の青いリンク**をクリックしてください。
これが一番の近道です。

> 左メニューから行く場合は **`Authentication (Preview)`** を選びます。
> ここだけ日本語化されておらず英語のまま表示されますが、これが「認証」の画面です。

開いたら次のとおり操作します。

1. **「シングルページ アプリケーション」** の欄を探す
   （既存の石材業務管理アプリの URI が既に入っています。**消さないでください**）
2. その欄の **［URI の追加］** をクリック
3. 次を貼り付ける

```
https://111rbubu-art.github.io/sekizaiwork/kintai/
```

4. 画面上部の **［保存］** を押す

**末尾の `/` まで含めて完全に一致している必要があります。**
1文字でも違うとログイン時に `redirect_uri` のエラーになります。

> Netlify でも公開している場合は、そちらのアドレス
> （`https://＜サイト名＞.netlify.app/kintai/`）も同じ手順で追加してください。
> **末尾のスラッシュまで含めて一致している必要があります。**

API のアクセス許可（`Sites.ReadWrite.All`）は既存アプリで既に許可済みのため、追加は不要です。

## 4. 実データを入れる

### 4-1. 社員マスタ（2名）

`KintaiEmployees` に2行つくります。`UserPrincipalName` は M365 のメールアドレスを
**完全に一致させてください**（ここが合わないとログインしても「登録がありません」と出ます）。

| Title | EmpName | UserPrincipalName | HireDate | EmpType | WeeklyDays | WeeklyHours | IsAdmin | Active |
|---|---|---|---|---|---|---|---|---|
| 001 | （社長の氏名） | 点検ページに出るアカウント名 | **空欄でよい** | 役員 | 5 | 40 | **はい** | **はい** |
| 002 | （社員の氏名） | その方のアカウント名 | 20XX-XX-XX | 正社員 | 5 | 40 | いいえ | **はい** |

役員は労働基準法上の労働者にあたらないため、年次有給休暇の付与対象ではありません。
`EmpType` を `役員` にすると、有給の画面は「対象外」と表示され、
休憩不足などの労基法由来の警告も出なくなります。打刻と労働時間の記録はこれまでどおり残ります。

### 4-2. 現場マスタ

まず本社と作業場を入れ、次によく行く霊園・寺院を足していきます。
既存の `data_*.js` にある寺院（慈宏寺・長泉寺・福寿院・光明院・願泉寺・宗福寺・久我山墓地など）
を登録しておくと、現場からの打刻がそのまま「その日どの現場にいたか」の記録になります。

| Title | SiteType | Lat | Lon | RadiusM | Active |
|---|---|---|---|---|---|
| 本社 | 事業所 | 35.xxxxxx | 139.xxxxxx | 150 | はい |
| 作業場 | 事業所 | 35.xxxxxx | 139.xxxxxx | 150 | はい |
| 慈宏寺 | 取引先 | 35.xxxxxx | 139.xxxxxx | 300 | はい |

半径は広めで構いません。アプリは測位誤差の分だけ半径をさらに広げて判定するため、
狭くしすぎると屋内で「事業所外」と判定されやすくなります。

## 4-3. 設定を点検する

リストを作り終えたら、**点検ページ**で確認してください。
列名の打ち間違い、選択肢の不足、`Active` の入れ忘れなどを自動で見つけて、
どこをどう直せばよいかを具体的に表示します。データは一切書き換えません。

```
https://111rbubu-art.github.io/sekizaiwork/kintai/check.html
```

「すべて問題ありません」と出れば、そのまま打刻を始められます。

点検している内容は次のとおりです。

- 6本のリストが作られていて、読み取れるか
- 必須の列がすべて揃っているか（不足していれば列名を表示）
- 選択肢の列に必要な値が入っているか（`出勤` `退勤` `位置情報同意` など）
- ログイン中の本人が社員マスタに登録されているか
- `Active` が「はい」の社員がいるか、管理者が1人以上いるか
- 入社日が `2019-04-01` の形式で入っているか（有給の計算に必要）
- 現場マスタに緯度経度の入った地点が登録されているか

## 4-4. 過去の勤怠を入力する（任意）

タイムカードや手帳に残っている過去の出退勤を、あとからまとめて登録できます。
**管理者だけが使える画面**です。

```
https://111rbubu-art.github.io/sekizaiwork/kintai/import.html
```

打刻画面の「管理」タブからも［過去の勤怠を入力する］で開けます。

### 使い方

1. **社員**と**月**を選ぶ
2. **まとめて入力** — 始業・終業を入れて［平日にまとめて入れる］。
   土日と毎月14日15日は自動で飛ばします
3. 違う日だけ、下の表で直す
4. ［この内容で登録する］

**休憩はあらかじめ60分が入っています。** 違う日だけ書き換えてください。

### 有給を登録する

表の「有給」の欄で **全日 / 午前半休 / 午後半休** を選びます。

- **全日**を選ぶと出退勤の欄が閉じ、その日は有給として登録されます
- **半休**は、働いた時間もあわせて入力できます（午前半休なら午後の勤務時間を入れる）
- **代休**も同じ欄から選べます（役員や入社日未登録の方でも選べます）
- 登録された有給は**承認済み**として扱われ、有給残日数と年5日の取得義務にすぐ反映されます
- 役員や入社日が未登録の方は有給の対象外なので、この欄は使えません

### Excel から貼り付ける

1行に「日付・出勤・退勤・休憩分」の順で並んでいれば、
タブ区切りでもカンマ区切りでも読み取ります。休憩分を省くと60分として扱います。
日付の次を「有給」とすると、その日は有給になります。

```
2026-07-01	08:00	17:30	60
7/2	8:00	17:00
3	08:15	18:00	60
7/10	有給
7/13	午前半休	13:00	17:30	0
7/17	代休
```

### 登録した内容を確認する・直す

登録済みの日は、**保存されている出勤・退勤・休憩・労働時間がそのまま表に表示されます。**
状態の欄には次の印がつきます。

| 印 | 意味 |
|---|---|
| 手入力 | この画面から登録した記録 |
| 実打刻 | 従業員がスマートフォンから打刻した記録 |
| 全日／午前半休／代休 など | 休みとして登録されている日 |
| ! | 休憩不足など、確認したほうがよい点がある日（カーソルを合わせると内容が出ます） |

**直したい日は、その行の［取消］を押してください。** その日の登録が取り消され、
すぐに入力し直せます。実際に打刻された記録も取り消せますが、確認の画面が出ます。

月まるごとやり直したい場合は、表の下の［この月の手入力を取り消す］が使えます。

### 手入力の記録の扱い

- 手入力した打刻には **「手入力」の印**がつき、実際に打刻したものと区別できます
- **誰がいつ手入力したかはサーバが自動で記録します**（作成日時・作成者）。
  記録の信頼性を保つための仕組みで、あとから消せません
- 位置情報は記録されません（当然のため、要確認の印はつきません）
- **既に打刻がある日は自動で飛ばします。** 上書きされる心配はありません
- 取り消しても記録そのものは消えず、「取り消し済み」として残ります。
  いつ誰が取り消したかも追えるので、監査の証跡が途切れません

## 4-5. 休日出勤と代休

休日に出勤したときの扱いには、**法律上まったく別の2つ**があります。
どちらを使うかで賃金が変わるので、就業規則で定めたうえで運用してください。

| | 振替休日（振休） | 代休 |
|---|---|---|
| 手続き | **事前**に休日と労働日を入れ替える | 休日出勤の**あと**に別の日を休みにする |
| 休日出勤日の扱い | 労働日になる | **休日労働のまま** |
| 割増賃金 | **不要**（週40時間を超えた分を除く） | **必要**（法定休日35%／所定休日は週40時間超で25%） |

> **代休を取っても割増分の支払い義務は消えません。**
> 代休で相殺されるのは賃金の100%部分だけで、35%（または25%）の上乗せは別途必要です。
> 割増を払いたくない場合は、**事前に**振替休日として処理してください。

### 代休の使い方

**発生**は自動です。休日に出勤した記録があれば、労働時間に応じて代休が発生します。

| 休日の労働時間 | 発生する代休 |
|---|---|
| 8時間以上 | 1.0日 |
| 4時間以上8時間未満 | 0.5日 |
| 4時間未満 | なし |

**取得**は、有給と同じ画面から申請します。「有給」タブの申請欄で種別に **代休** を選びます
（代休の残がある場合だけ選択肢に出ます）。管理者が承認すると残日数から引かれます。

**期限**は発生から3か月です（`config.js` の `KT_COMP.expireMonths` で変更できます）。
期限が30日を切ると本人と管理者の画面に警告が出ます。取得は**古い発生分から順に**消化されるので、
放っておいて失効する分が最小になります。

役員も休日出勤すれば代休が発生します（代休は労基法の権利ではなく会社の取り決めのため）。

### 振替休日の使い方

`KintaiHolidays` リストに **2行**入れます。日の種別そのものを入れ替えます。

| Title | HolidayDate | HolidayType |
|---|---|---|
| 振替出勤 | 2026-07-11（出勤する土曜） | `平日` |
| 振替休日 | 2026-07-13（休む月曜） | `所定休日` |

こうすると 7/11 は平日扱いになるため休日労働の割増が発生せず、代休も発生しません。
7/13 は休日扱いになります。**出勤する前に**登録してください。

## 6. 運用のこつ

- **打刻を間違えたとき** … 打刻ログは書き換えられません。管理者が該当行の `Voided` を「はい」にし、
  `VoidReason` に理由を書いたうえで、正しい行を新しく追加してください。履歴が残り、監査に耐えます。
- **要確認の打刻** … 管理タブに一覧が出ます。内容を確認したら「確認済」を押すと消えます。
- **月次の給与処理** … 管理タブ → 月次集計 → 「CSVを書き出す」。
  Excel でそのまま開けます（文字化けしません）。
- **年5日の取得義務** … 管理タブの「有給の状況」に期限と残り日数が出ます。
  赤字になったら会社側から取得日を指定してください（労基法39条7項）。
- **打刻ログが増えたら** … 数年分たまって動作が重くなったら、
  3年より古い行を CSV に書き出したうえで削除してかまいません（法定保存期間にご注意ください）。

## 7. 設定を変えるとき

変更するのは `kintai/config.js` だけです。主なもの：

| 変えたいこと | 場所 |
|---|---|
| 法定休日の曜日 | `KT_HOLIDAY.legalWeekday`（0=日曜） |
| 所定休日の曜日・日付 | `KT_HOLIDAY.companyWeekdays` / `companyDays` |
| 位置取得の待ち時間 | `KT_GEO.timeoutMs` |
| 現場の既定の判定半径 | `KT_GEO.defaultRadiusM` |
| 有給の基準日の考え方 | `KT_LEAVE.baseDateMode`（`hire`=入社日基準） |
| 二重打刻とみなす時間 | `KT_PUNCH.dedupeMin` |

変更したら `KINTAI_VERSION` と `sw.js` の `KT_CACHE` の番号も上げてください。
上げないと、端末に残っている古いファイルが使われ続けます。
